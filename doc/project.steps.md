## План действий:
* Выбор библиотек:
    * Рассмотрите использование библиотеки для работы с сетью, например, Boost.Asio для реализации сервера и клиентов.
    * Вы можете использовать сторонние библиотеки для упрощения работы с JSON (например, nlohmann/json).

* Разработка базовой архитектуры:
    * Определите протокол взаимодействия между клиентами и сервером. Например, клиент отправляет запросы на добавление, получение и удаление данных.
    * Разработайте базовые классы для представления объектов в базе данных, например, Document.
    * Определите формат хранения данных в базе (например, JSON).

* Сервер:

    * Создайте сервер, который использует Boost.Asio для асинхронного обслуживания нескольких клиентов одновременно.
    * Реализуйте обработчики для запросов от клиентов.
    * Создайте хранилище данных, где каждому ключу соответствует объект (документ) в базе данных.
    * Реализуйте операции добавления, получения и удаления данных в базе.

* Клиент:
    * Реализуйте консольное приложение, в котором пользователь может отправлять запросы к серверу.
    * Определите структуры данных для представления запросов и ответов.
    * Используйте Boost.Asio для общения с сервером через сетевой протокол.

* База данных:
    * Разработайте класс для хранения данных в формате key-value, например, используя std::unordered_map.
    * Реализуйте функции для добавления, получения и удаления данных в хранилище.

* Тестирование:
    * Напишите тесты для сервера и клиента, чтобы удостовериться, что база данных работает корректно.
    * Проверьте, что сервер обрабатывает несколько клиентов параллельно.

* Обработка ошибок и безопасность:
    * Добавьте механизм обработки ошибок на сервере и клиенте.
    * Рассмотрите вопросы безопасности, такие как предотвращение SQL-инъекций (если применимо).


# Примерная архитектура:
* Серверная часть:
    * Класс Server:
        * Использует Boost.Asio для асинхронного обслуживания клиентов.
        * Реализует методы для обработки запросов и отправки ответов.
        * Внутри содержит объект базы данных.
    * Класс Database:
        * Хранит данные в виде key-value.
        * Реализует методы для добавления, получения и удаления данных.
    * Структура Document:
        * Представляет объект в базе данных.
        * Может быть расширена в зависимости от потребностей.

* Клиентская часть:
    * Класс Client:
        * Взаимодействует с сервером по сети.
        * Отправляет запросы и получает ответы.
        * Имеет консольный интерфейс для пользователя.

    * Структуры запросов и ответов:
        * Определите формат запросов и ответов между клиентом и сервером (например, JSON).
        * Например, запрос на добавление данных может иметь следующий формат: {"action": "add", "key": "some_key", "value": {...}}.

    * Обработка пользовательского ввода:
        * Реализуйте интерфейс командной строки для отправки запросов к серверу.
        * Обрабатывайте ввод пользователя и отправляйте соответствующие запросы к серверу.
